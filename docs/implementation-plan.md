# 实现步骤与原子提交计划

> 本文是实现前计划，不构成实现、P1 试点、迁移、EULA 接受或运行环境启动批准。每个未来提交应是可审阅、可回退的完整变更单元，而不是按单个文件拆分。当前批准基线仍为 Forge 1.20.1 服务端常驻身体；真实客户端是候选，未经用户明确决定不得静默替换路线。

## 现状、范围与路径约定

当前仓库是文档蓝图：`docs/` 保存需求和验证边界，`contracts/examples/` 是历史示例，`bridge/forge/` 与 `server/` 只有说明。没有已实现的 Forge 模组、机器 Schema、传输端点或上游 AgentLuo API 可直接调用。已提交的约束以[产品需求](product-spec.md)、[集成架构](architecture.md)、[接口语义草案](interface-draft.md)、[身体验证](body-validation.md)和[路线图](roadmap.md)为准。

当前工作树另有尚未提交的 P0 准备记录与资源清单；其内容不是本次原子文档提交的前置依赖。根据该工作树上下文，已下载并校验但**未安装、未执行**的候选工件包括 Forge `1.20.1-47.4.28` installer/MDK、Minecraft client/server jar、Diet 与 Farmer's Delight；客户端 libraries/assets 仍未取得，配置 hash 仍待生成。工件存在不代表兼容、可启动或获准试点；若这些准备记录未随后的提交保留，应在 C01 前重新核验。

未来代码根目录、模组标识、包名、测试框架和实际传输实现均尚未决定。本计划以“拟议 Forge 实现目录”“拟议非游戏测试目录”描述新增路径；在 C01 中确定后才写入真实路径。AgentLuo 侧改动必须在其上游仓库以独立 PR/提交进行，本仓库不复制人格、WorldStage 或 Agent 实现。

## 共同门槛

- C01 前不解压/执行 MDK、installer、jar 或 Gradle；需维护者对隔离构建范围单独批准
- P1 前还需冻结候选包、配置和 SHA-256，确定离线登录身份与网络边界，完成隔离世界/区域、备份、人类玩家对照及 P1 单独批准
- 离线登录不依赖 Microsoft/Mojang 在线认证，但昵称或派生 UUID 不是可信身份；身体控制激活前仍须独立认证与绑定。不得猜测改名/后端切换后的 UUID 或 playerdata 迁移行为
- 高风险挖掘、放置、战斗、库存和容器变更默认关闭。食物/容器返还仅限经书面授权的隔离身体语义测试，不成为 Agent 的生产能力
- 世界结果不能靠 Git 回退；涉及世界的提交只可回退代码，实际世界须按备份与恢复流程处理

## 路线选择规则

C07-A 与 C07-B 是条件分支，不要求同时完整实现。先由最小候选验证包、真实玩家基线和 C06 的证据决定是否需要服务端身体比较；真实客户端的 P1 批准也不等于迁移批准。C08 只接入获选且经批准的一条身体驱动路线，但继续复用 C02-C06 的共同契约、安全和测试边界。

C07 先提交候选驱动与非游戏测试，不立即接收实际控制。C08 可先提供候选路线所需的最小保护并开展已授权隔离试验，再由试验结果确认是否采用；不要求先证明路线成功才允许建立保护。任何候选身体被实际控制前，服务端身份绑定、停止、区域及禁止交互保护必须就绪；缺失时保持拒绝控制。若试验否决该候选，保留证据并回退驱动，不把试点批准当作正式选路批准。

服务端路线保持默认基线，直到用户在证据基础上明确选路。若任一身体路线不能保持普通玩家食物/Diet、持久身份、清理和恢复不变量，应停止扩展并提交人工决定。

## 实现时的测试分层

| 层级 | 可自动执行 | 需要人工/真实游戏 |
| --- | --- | --- |
| 非游戏单元 | 类型、策略、epoch、回执、授权、绑定接口、输入释放和故障状态机 | 无 |
| 构建集成 | 选定 MDK 下的编译、格式、静态检查和不启动游戏的适配测试 | 依赖与实际 Forge API 审阅 |
| 隔离 runtime | 仅保留日志/证据格式校验 | 食物、Diet、容器返还、tick、保存、重启、离线登录 UUID/playerdata、数据包强制与控制丢失 |
| 人类/邀请者 | 测试记录完整性 | 同配置正常玩家基线；2 小时、3–5 人受邀者里程碑，当前未执行 |

连接/heartbeat 失效与模型推理变慢必须分开测试：前者触发停止、保存、移除，后者不得触发断连。重启恢复必须重新认证、观察、对账；每个持久身体身份最多一个活动身体，只有当前 epoch 有效，单个运行时最多一个改世界动作。
