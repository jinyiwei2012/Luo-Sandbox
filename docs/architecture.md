# 总体架构草案

> 状态：提案，待人工评审；不代表已经实现、可运行或已完成安全验证。

## 目标

Luo-Sandbox 计划支持多个独立世界中的 AI Agent 闭环：世界端口产生观察，认知层提出行动计划，受控执行器实施允许的行动，再把行动回执与后续观察返回。世界端口应可替换，业务核心不应依赖 Minecraft API。

## 分层与职责

| 层 | 计划职责 | 不负责 |
| --- | --- | --- |
| Domain | `Stimulus`、`ActionPlan`、`ActionResult`、`WorldObservation` 等稳定契约 | 网络、游戏 SDK、模型厂商细节 |
| Adapter | HTTP、stdio 或世界事件到领域语义的转换 | 决策或直接写世界状态 |
| Stage | 会话生命周期、队列、截止时间、取消与 actor 调度 | 游戏协议实现 |
| Agent | 认知、记忆策略、技能编排与计划生成 | 获得任意系统命令能力 |
| World | 世界事实、允许行动的校验与执行结果 | 直接暴露不可信文本为事实 |
| Infrastructure | 模型、存储、配置与日志的可替换适配 | 领域策略 |
| Composition root | 显式依赖注入与启动装配 | 隐式全局单例 |

未来主控候选为 Python 编排器；世界桥接候选为 Node 进程。此处只定义边界，不提供依赖、入口或运行承诺。

## 本地桥接协议

Python 与 Node 候选通过本机 NDJSON stdio 通信：每行一个 UTF-8 JSON 对象，双方仅接受版本已知、`kind` 已知且字段通过校验的消息。stdio 管道不等同于可信输入；桥接器仍须验证世界、身份、epoch、行动类型、参数上限和时间限制。

初始消息种类为：

- `world.observation`：事实快照或增量，以及与事实分离的原始/不可信文本
- `action.request`：主控请求的受限行动
- `action.result`：桥接器的终态回执，引用请求的 `action_id`

样例见 [contracts README](../contracts/README.md)。样例是说明材料，不是运行时 JSON Schema。

## 身份、顺序与终态

每个请求与回执必须带有 `schema_version`、`action_id`、`world_id`、`agent_id`、`session_epoch` 和 ISO 8601 `timestamp`。`session_epoch` 在桥接重连或世界会话更替后递增；旧 epoch 的请求一律拒绝，旧事件不得驱动新会话决策。

单个 `(world_id, agent_id, session_epoch)` 同时只能有一个改变世界的行动。计划中的终态为：`succeeded`、`failed`、`timed_out`、`cancelled`、`disconnected`、`unknown`。超时、取消或断连并不证明行动未发生；若结果为 `unknown`，上层应通过新的观察或人工介入确认，禁止盲目重试变更操作。

## 队列、取消与授权

Stage 计划维护有界队列，并在容量、行动持续时间、截止时间和取消上施加限制：

- 高速观察可按最新快照或同类 delta 合并，明确记录合并语义
- 行动请求与最终回执不可因观察拥塞而静默丢失
- 取消是对正在进行或排队行动的显式请求，结果仍必须落入一个终态
- 桥接器只接受已授权的 `world_id`、`agent_id` 与行动白名单
- 每项行动有固定参数边界和最长执行时间；LLM 不获得任意 JS、shell 或游戏命令通道

计划中的事件账本应保存请求、接受/拒绝、取消、终态回执和关联观察的最小审计信息。它服务于回放和排障，不等同于事实数据库，也不应记录凭据。

## 世界事实模型

`WorldObservation` 计划区分：可验证的事实快照/增量、来源元数据，以及不可信文本（聊天、告示牌或服务端文本）。认知层可参考文本，但不得把它未经验证地提升为权限、位置、库存或行动完成事实。行动完成以可靠 `action.result` 与后续事实观察共同判断。
