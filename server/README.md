# Agent-LuoTianyi 集成侧边界草案

> 未实现。此目录不包含服务入口、依赖清单或可启动代码；名称沿用目录骨架，后续可经人工评审改名。

这里不是新的 Python 编排器或独立认知服务。Agent-LuoTianyi 侧集成适配器已纳入协调交付范围，复用其既有组合根、Agent、WorldStage 与基础设施能力，并与 Luo-Sandbox 的 Minecraft 契约通信；源码仍在上游仓库以独立原子提交/PR和测试实现，当前未开始，等待实际接缝确认。服务端直接产生权威观察与事实回执，不经真实客户端转发；根据复杂度、兼容性证据和可复现性，可采用自有 Forge 伴随模组或小范围服务端源码改动，未预先决定 core fork 技术。传输、连接方向和具体认证机制尚未决定，旧 NDJSON 不是当前定案。

计划职责：

- 在上游仓库将 Minecraft 客户端局部观察、服务端权威观察和事实回执映射为 `Stimulus`/WorldStage 输入，并将 `ActionPlan`/技能决定映射为类型化 Forge 客户端行动
- 配合上游的会话、截止时间、有界队列、取消和单一变更行动约束，不接管业务调度
- 审核 `world_id`、洛天依运行时映射、`session_epoch`、行动白名单及参数边界
- 支持最小事件账本的集成方案，供未来回放、排障和人工审计

模型、存储和配置仍属于上游基础设施适配层。本仓库不声称上游现有 HTTP/WebSocket 已支持新行动；模型输出只能经上游受限技能形成被验证的计划候选，不得获得 JavaScript、shell、NBT、反射或未受限游戏命令执行能力。服务端源码改动已获实现授权以降低中继或适配复杂度，但必须小范围、记录来源/固定版本/补丁/许可证并通过对应上游构建与测试；游戏线程仅提取最小快照，经异步有界队列交付，不能等待网络 IO 或 LLM。该授权不等同 runtime、EULA、世界动作或二进制分发批准。接口语义见[草案](../docs/interface-draft.md)。
