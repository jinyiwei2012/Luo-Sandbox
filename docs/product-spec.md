# 已批准产品需求

> 用户已确认产品意图；实现设计、参数和可行性仍待验证。

## 愿景与首个里程碑

Luo-Sandbox 让同一位由 Agent-LuoTianyi 驱动的洛天依，在公开自定义 Forge 1.20.1 服务器中通过受项目控制的真实 Forge 客户端活动，并由服务端伴随模组独立实施安全权威与事实回执。她可与玩家共同生活：先稳定观察、上游决策、公开聊天与有限移动、如实反馈；随后仅在持续验证和单独批准下发展更多能力。

首个里程碑不含全自动生存、耕作、烹饪、建造、战斗或容器修改。所有玩家能请求，她可依人格、关系、记忆和技能接受、拒绝或协商。单条行动主线可被对话插入。长期可选的可恢复玩笑必须 opt-in、可撤销，首阶段不执行。

## 身体、区域与状态

- 一个固定离线游戏身份绑定到一个经独立认证的控制会话；昵称或离线派生 UUID 不是控制授权，也不主张账户所有权
- 任一时刻仅一个当前 epoch、最多一个改变世界的动作；活动仅限管理员授权的单一维度和有限安全区域
- 保护生存保留正常饥饿、营养和状态规则，致命伤害另行拦截；不是创造、无限饱食或持续治疗
- 控制会话确认失效时客户端必须停止持续输入、保存并登出/移除受控会话；不是实体击杀或掉落，LLM 变慢不触发此路径
- 重连、客户端/模组更新或版本变更后须重新认证、同步配置与版本、重新观察、对账再恢复；不盲重放
- 位置、维度、生命、背包、效果和已实现营养状态以真实客户端/服务端实际行为为准，逐项核实

真实客户端的人类玩家语义是当前基线。`ServerPlayer` 派生与 `FakePlayer` 是历史替代/对照资料，不是必须比较的采用门。详见[身体验证](body-validation.md)。

## 行动与安全

首个白名单仅为公开聊天、`look_at` 与有界普通行走；状态查询与有限脱困仅在后续明确批准后开放。行走受服务端普通游戏数据包路径上的身份、会话、区域、禁止交互和速率检查约束；卡住后才允许有限辅助恢复，并只能在预先登记的安全目的地中选择。无安全能力即停止并如实说明。

禁止原始命令、Java、NBT、反射、OP、`give`、天气控制及未列入白名单的执行。挖掘、放置、攻击、库存与容器操作默认禁用，需逐项审查、授权、审计与恢复验证后才能开放。

## 运行与体验

可选的有限主动性只在安全区运行。公开且已结算的体验应在重启后、不同客户端间可用，但不是所有聊天永久保存；额外受限状态绝不进入公开记忆。离线登录不依赖 Microsoft 登录，也不声明游戏或内容所有权；许可证与 EULA 义务不因此消失。用户偏好低活动保持连接，但安全与绝对限制优先。

默认访客可进行公开互动，无需绑定。只有建立跨平台关联时，才须人工验证 Minecraft 与 AgentLuo 账户控制权并登记 MC UUID 与上游 `user_uuid`；绑定可撤销，昵称不是身份或私有授权。所有访客默认公开身份/权限档，日后可预留自助绑定，但绑定不扩张私有访问权。

隐私、感知和能力降级的完整约束见[感知与隐私矩阵](perception-and-privacy.md)。
