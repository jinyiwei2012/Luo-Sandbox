## 验证登录与控制身份边界

验证环境已计划使用离线登录，不依赖 Microsoft/Mojang 在线认证或账户登录；这是用户确认的规划选择，尚未配置或测试。该选择不解释所有权，也不改变适用的许可证与 EULA 义务；本文不提供启动器、二进制或认证绕过指引。下载也不因此变为离线，仍按来源与 hash 记录。

- 离线昵称及其派生 UUID 不是加密身份，可能被冒用；固定昵称只能作为稳定映射候选，不是已验证的用户身份
- 改名或更换认证后端时 UUID/玩家数据的实际行为必须验证；不得猜测 UUID，须先制定有意的安全迁移和 playerdata 处理规则
- 单一持久身体身份、仅当前 epoch 有效和单运行时单个改世界动作仍适用
- 身体连接在控制激活前仍须完成独立认证与绑定；具体保护/绑定机制待设计与测试，不预设可用方案
- 隔离环境应限制在本地回环或受控私有网络，并由防火墙和显式访问控制保护；不得暴露公开的未认证端点。离线模式下白名单本身不是可信身份边界
- 不要求为本验证计划准备已购买的 Microsoft 账户；离线皮肤行为未知，不承诺官方皮肤或显示结果

## 最小证据记录约定

建议每次试验使用目录 `evidence/YYYY-MM-DD/<run-id>/`（运行产生后再由维护者决定是否纳入版本控制），包含：

- `manifest.md`：本页环境清单的冻结副本、授权范围、操作者和开始/结束时间
- `human-baseline.md`：人类参考的操作、前后状态、观察来源与差异
- `cases.md`：每个用例的前置条件、步骤、预期、实际、证据路径和结论
- `events.log`：时间顺序的 session、epoch、请求、取消、回执、停止与恢复事件；不得含凭据
- `artifacts.sha256`：所用已获准 jar、配置和数据包的文件名与 SHA-256
- `failures.md`：失败、未知、偏差、清理状态和是否需要人工决策

`run-id` 应可关联世界、候选路线和当前 epoch，但不使用真实账户秘密或私有标识。观察记录须标明来源、时间、新鲜度和受众。

## 安全控制核对

- Forge 与 AgentLuo 的独立进程链路须认证；认证材料仅在获准的运行环境配置，不入仓库
- 服务端须在普通游戏数据包路径独立执行身份、会话、区域、禁止交互和速率限制；不能只依赖自定义包或按键过滤。无论使用伴随模组或源码改动，游戏线程均只提取最小快照，经异步有界队列发送，不等待网络 IO 或 LLM
- 每个持久身体身份至多一个活动身体；仅当前 epoch 有效；单个运行时至多一个改变世界的动作
- 停止、取消、超时和控制丢失的执行责任、触发方式和日志位置须先指定；紧急停止不等待 LLM
- 服务端直接产生的权威观察/回执、客户端局部观察和授权相互分离；世界文本不构成权限，`unknown` 不当作未发生
