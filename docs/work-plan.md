# 工作计划：真实 Forge 客户端主路线

> 本文是当前工作拆解，不是 runtime、EULA、世界或动作范围批准。真实客户端主路线已获用户锁定；离线基础与禁用执行传输已有受限实现证据，但仓库尚无控制 runtime、真实客户端测试或生产验证，范围不会因本计划自动扩张。当前证据见[集成实施状态](integration-status.md)。

## 当前快照

- 已批准基线是 Forge 1.20.1 真实客户端、类型化控制与服务端直接安全权威；Agent-LuoTianyi 是人格、认知、关系/记忆、接受或拒绝及高层目标的唯一来源
- 目标是普通玩家/模组环境中的生活语义；真实人类玩家是受控真实客户端的对照基线
- `ServerPlayer`/`FakePlayer` 仅保留历史替代资料，不是主路线或必须比较门
- GameScaling 如被单独评估，只能在已授权帧和短动作历史上提议短输入动作；它不是验证器、第二个心智或权限来源
- 服务端直接产生的世界观察和权威回执才建立结果，不经客户端转发；可按复杂度、兼容性证据和可复现性选用自有 Forge 伴随模组或小范围源码改动，主模型目标、确定性授权与世界回执必须分离
- 验证登录模式已计划为离线登录，不依赖 Microsoft/Mojang 在线认证；该选择尚未配置或测试，且不改变 Agent 控制链路必须独立认证和绑定的要求
- Agent-Luo 适配器、离线契约/认证基础和禁用执行心跳传输已有分阶段实现；它们不等于完整上游认知装配、生产端点或 runtime 批准

详细边界见[产品需求](product-spec.md)、[架构](architecture.md)、[身体验证](body-validation.md)、[接口草案](interface-draft.md)、[路线图](roadmap.md)与[来源记录](provenance.md)。

## 分阶段任务

### P0：准备与验证设计

1. 根据候选研究协作选择最小验证包，冻结版本、依赖、配置 hash、硬件、离线登录身份与隔离环境输入，记录人类正常玩家参考基线
2. 设计食物、Diet、模组事件、保存和重连的正负验证用例、记录格式与证据判定
3. 明确试点范围、允许观察和非破坏性动作，以及不启用生产背包或其他动作权限的边界

**完成门槛：** 具备版本矩阵、人类参考基线和可复现验证设计；P0 不实施或比较服务端身体。进入 P1 前须获用户对 P1 隔离试点的单独批准。

### P1：小型真实客户端基线试点

1. 仅在 P0 输入和 runtime 授权齐备后，在隔离范围内做无 LLM 的真实客户端最小试点，以类型化控制和确定性寻路为基线
2. 执行食物、Diet、模组事件、保存、重连、输入释放和服务端停止测试，与同配置人类玩家对照；不扩大为生产库存或世界交互
3. 记录主路线运行证据、客户端/服务端版本配置同步和服务端安全拦截；若选用源码改动，记录基线、补丁、许可证和可复现构建/测试；不因成功自动开放新能力

**默认安全：** 禁止挖掘、放置、战斗、容器和库存变更。客户端输入受能力、区域、截止时间、取消、新鲜度与互斥检查；服务端在普通游戏数据包路径独立校验身份、会话、区域、禁止交互和速率。游戏线程只提取最小快照，异步侧经有界队列发送，不等待网络 IO 或 LLM。源码改动不得绕过认证、隐私/受众过滤或动作白名单。不得声称权重、检查点许可证、Forge 兼容性或模型可靠性已经验证。GameScaling 基准仅在 P3 可靠基线后按 P4 评估。

### P2：协议、上游适配与独立授权

1. 定义版本化的观察、类型化动作、取消、`session_epoch` 和终态回执契约
2. 将上游短而有界目标与确定性执行信封分开：批准目标/区域、动作能力、截止时间、取消和会话新鲜度均可审计
3. 在 Agent-LuoTianyi 仓库实现适配器并以独立原子提交/PR和测试交付；确认实际接缝后完成 Minecraft 契约的离线往返，世界回执不由模型或提议器代替

**完成门槛：** 陈旧 epoch、未知能力、越界或未授权动作被拒绝或如实标记；动作与终态回执不静默丢失。该阶段不自动开放高风险能力。

### P3：首个集成闭环

1. 仅实现公开聊天、`look_at` 与有限普通行走，返回如实的权威回执
2. 验证控制失去时的停止、保存、移除：连接/会话确认失效才触发；模型变慢不得触发
3. 拒绝旧 epoch 的结果；`unknown` 先经新鲜观察与对账后再决定是否采取后续动作，不对陈旧结果盲目重试

**完成门槛：** 在既有路线图定义的 2 小时、3–5 位受邀测试者目标服务器集成中复现停止、恢复、隐私/身份过滤、能力降级和如实反馈。该测试目前**未执行，不得宣称通过**。

### P4：可选 GameScaling 基准

仅在 P3 的可靠基线之后，进行任务专项、隔离的效益比较。记录精确环境、延迟、内存、成功/失败/被禁止的提议、取消、输入释放与安全结果；不以基准自动批准生产采用。

## 运行安全不变量

- 控制或会话确认失效：停止、保存并移除身体；模型变慢不等于失联
- 取消或超时：释放全部持续按键/输入；陈旧 epoch 和过期结果不得重放，`unknown` 先经新鲜观察与对账处理
- 每个持久身体身份至多一个活动身体；仅当前 epoch 有效，单个运行时至多一个改变世界的动作；恢复前重新认证、观察和对账
- 高风险能力默认关闭；隔离测试不授予生产动作或库存权限
