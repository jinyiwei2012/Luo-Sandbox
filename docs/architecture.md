# Agent-LuoTianyi × Forge Minecraft 集成架构

> 已批准方向；离线契约、基础认证和禁用执行传输已有受限实现，但 Forge embodiment、生产装配与 runtime 验证仍为草案或未验证。证据范围见[集成实施状态](integration-status.md)。

## 所有权

| 边界 | 负责内容 | 明确不负责 |
| --- | --- | --- |
| Agent-LuoTianyi（上游适配器） | 洛天依人格、认知、对话、关系/记忆、接受或拒绝、技能、决策与 Agent/WorldStage 调度；在上游仓库把 Minecraft 契约映射为 `Stimulus`/WorldStage 输入，并把 `ActionPlan`/技能决定映射回类型化动作意图 | Minecraft 实体、Forge API、新的业务规划器或独立认知运行时 |
| Luo-Sandbox | Minecraft 契约、真实客户端控制、服务端安全权威、授权观察、事实回执与审计边界 | 上游 `Stimulus`/WorldStage 或 `ActionPlan` 的适配实现、人格/记忆/决策所有权 |
| Forge 客户端控制器 | 真实客户端侧有限感知、类型化输入执行、输入释放、连接/会话生命周期 | 对 LLM 开放任意命令、客户端类加载到专用服务端或权限提升 |
| 服务端权威实现 | 以自有 Forge 伴随模组或小范围服务端源码改动实现独立认证绑定、普通数据包路径安全检查、保护、权威观察/事实回执与审计 | 代替上游决策、只依赖自定义包实施安全，或暴露任意执行接口 |

可以复制或改造上游实现，但人格、认知、记忆与决策始终以上游为事实来源。上游适配器已纳入协调交付范围，仍必须在 Agent-LuoTianyi 仓库以其独立的原子提交/PR和测试实现；当前尚未开始，等待实际接缝确认。导入模块须保留许可与来源记录，共享修复优先上游。`server/` 是该上游集成边界的说明，并非新增编排服务。

## 部署与线程边界

主路线是 Forge 1.20.1 真实客户端具身和服务端直接权威路径。控制客户端使用固定离线游戏身份，但仅在经独立认证并绑定的控制会话中激活；昵称或 UUID 不可信，不构成授权或所有权声明。服务端直接产生世界权威观察与事实回执并对接待定集成接口，不经客户端转发；真实客户端移动仍走普通游戏数据包路径。服务端可根据实际复杂度、兼容性证据和可复现性，在自有 Forge 伴随模组与小范围服务端源码改动间选择，未预先决定 core fork 技术。最终跨进程/跨仓库传输、连接方向和具体认证机制均未决定；旧本地 NDJSON 仅是历史候选。Forge 与 AgentLuo 进程之间必须认证，游戏线程不得等待 IO 或 LLM。客户端与服务端可从一个共享源模组按物理 side 隔离，禁止专用服务端加载客户端类；单/多 JAR 打包尚未决定。

真实客户端的人类玩家行为是当前身体基线。`ServerPlayer` 派生和 `FakePlayer` 是历史替代路径，可在需要时作为对照研究，既不是主路线也不是实现前比较门。目标模组兼容清单是验证目标而非全量承诺：Farmer's Delight、Neapolitan、Diet、Serene Seasons、Macaw's Furniture、Storage Drawers、JEI、AppleSkin、小地图及 Forge 兼容优化模组。煨茶酝露疑为 HerbalBrews，须先核对实际 artifact；Sodium 及具体构建版本不预设。

## 身体与恢复

固定离线身份只绑定一个当前控制会话；活动范围限管理员授权的单一维度和有限安全区域，边界不得静默扩大。保护生存应保留正常饥饿、营养及常规状态规则，致命保护须由服务端独立实施；不等同创造模式、满饥饿或持续回血。Diet 与饥饿须在真实客户端和同配置人类玩家基线中验证，不能承诺完整模组一致性。

已确认的控制会话失效应停止输入、保存并正常登出/移除受控会话，不以死亡/掉落或实体击杀代替；LLM 慢不等于断连。恢复顺序是重新认证、核验客户端/服务端/模组版本与配置、重新观察、对账后恢复；旧 epoch 不得盲目重放动作。模组离线保存语义逐项验证，不能假定普遍冻结。见[身体验证](body-validation.md)。

## 生命周期与执行

每个持久身体身份在任一时刻最多一个活动控制会话，只有当前 `session_epoch` 有效；单个运行时跨 epoch 同时最多一个改变世界的动作。回执终态至少区分成功、失败、超时、取消、断连和 `unknown`；不确定不代表未发生，恢复后必须重新观察而非盲重试。观察可在有界队列中合并；动作请求与终态回执不可静默丢失。

第一阶段允许白名单中的状态、有限表达、回家/脱困和普通行走；`look_at` 只用于传输冒烟。普通行走优先，须有界尝试与卡住证据后才能进行受约束辅助恢复；多个已批准安全目的地应限速、重检安全，并记录理由、尝试和实际结果。不得传送其他玩家，也不得无限重试；没有安全移动能力即停止并如实通知。

高风险挖掘、放置、库存/容器与战斗默认禁用，直到逐项授权和验证。明确 Minecraft 接入的行动集合、授权来源和限流值仍待定。

## 客户端控制与服务端权威

真实 Forge 客户端控制器是已锁定的主路线，但 runtime、EULA、世界和动作范围仍须逐项批准。Agent-LuoTianyi 仍是人格、认知、关系/记忆、接受或拒绝及高层目标的唯一来源。主模型只给出短而有界的任务；确定性执行信封须含已批准目标/区域、动作能力、截止时间、取消和会话新鲜度。

默认使用类型化 API 与确定性寻路。持键输入的所有权必须独占于确定性执行路径或获批模型提议路径之一；取消、超时、会话失效或客户端丢失均释放全部输入，服务端同时停止授权。若有任务专项证据，GameScaling 才可作为可选动作提议器：仅基于当前已授权帧和短动作历史提议短键盘/鼠标动作。它不是计划验证器、候选评分器或安全裁判；原生候选评分未验证，受限目标遵循可靠性未知，不能成为第二个心智或自行升级权限。动作块约 200ms 不等于推理延迟；主模型只在完成、失败、卡住或状态变化时复查。

服务端权威实现须独立在普通游戏数据包路径上执行身份、会话、区域、禁止交互和速率限制；只过滤自定义包或按键不足以保证安全。服务端是世界权威观察和事实回执的直接生产者，可直接发送到待定的集成接口；这不预设 API、传输方向或客户端中继。已授权的小范围服务端源码改动可降低中继或适配复杂度，但不能绕过认证、隐私/受众过滤、动作白名单或普通包路径执法，且不得在游戏线程等待网络 IO/LLM：游戏线程只提取最小快照，异步侧经有界队列发送。主模型的意图复查、确定性权限检查与实际回执成功必须分开；两个模型同意也不是安全证明。客户端帧是可选感知来源，遵守来源/受众过滤；已加载区块不等于无视线、全世界或隐私全知。禁止原始任意游戏命令、Java、NBT 或 OP。挖掘、建造、战斗和库存变更仍默认禁用；服务端热修复不得通过 OP 命令、通用 Java/NBT 工具开放。仅经显式隔离授权的食物测试可使用必要物品，且不成为生产能力。每项源码改动须记录来源、精确基线版本、补丁和许可证，并在对应上游构建与测试中可复现；这项实现授权不批准游戏启动、EULA 接受、世界动作或二进制分发。

## 事实、记忆与能力

世界文本永远是不可信输入，不能授予权限。动态数据源丢失时立刻标为陈旧，不能指导当前动作；静态规则和地标可继续引用。历史记忆不是当前事实，记录时应带来源、时间和用途。适配器可通过能力协商使用已授权、可靠的增强能力；缺失、不兼容或离线必须表达为不可用/未知，不能降级为零值、完整值或默认值。模组 GUI 可展示健康信息，不等于机器数据通道。

详细语义见[接口草案](interface-draft.md)，可见性与隐私见[感知与隐私](perception-and-privacy.md)。
