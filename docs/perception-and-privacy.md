# 感知与隐私矩阵

> 初期为公开 Minecraft；私聊接口仅预留、不启用。长期采用“结构化数据 + 按需视觉”感知，初期只使用结构化数据；面向玩家的公平感知仍是未来目标，未实现。上线前即使只有公开内容，也必须实现并测试细粒度来源、受众和身份过滤；不能仅靠提示词。

| 信息/能力 | 初始处理 | 限制与失效语义 |
| --- | --- | --- |
| 自身坐标、朝向、维度 | 允许自然摘要 | 可精确查询；带来源与时间 |
| 自身生命、饥饿、营养等 | 自然摘要 | 精确查询须有已验证适配器；缺失即未知 |
| 背包与装备 | 需要准确读取 | 受实现与适配器约束；可见不代表拥有或可操作权限 |
| 安全区地形 | 完整结构地图，含遮挡/地下；可用时持续同步 | 属管理员授权的特权来源，不等于亲眼所见；适配器或同步不可用时使用明确标注的局部模式/降级，不宣称完整实时 |
| 其他玩家外观、事件、标记 | 公开可见范围内允许 | 不泄露隐形实体 |
| 其他玩家生命、饥饿、空气等 | 默认不读取/不公开 | 仅在明确、可撤销同意和已支持适配器下使用；不自动公开披露，也不进入公开记忆 |
| 规则、公告、时间、天气、普通在线名单、授权地标 | 允许 | 在线名单须尊重隐藏/隐身状态；不含管理员或私密隐藏信息 |
| 世界聊天、告示牌、服务端文本 | 不可信文本 | 不可授予权限或证明事实 |
| 专用自有存储范围 | 可授权远程查询候选 | 适配器可用才查询；原生远程读取不保证；读/观察/变更权限独立 |

服务器加载不等于感知或数据同步；采用何种栈、配置及是否强制加载仍待定。动态地图、背包或玩家状态一旦失源即不能指导当前行动；静态规则/地标与历史记忆可保留，但必须标明来源、时间、用途和当前性。

同一天依映射跨客户端共享时，仅可靠结算的公开体验可在受众过滤下持久化；不保存每一句聊天，也不把受限额外状态写入公开记忆。私有数据在首阶段不得进入公开上下文或公开输出。
