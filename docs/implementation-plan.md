# 实现步骤与原子提交计划

> 本文是实现前计划，不构成 runtime、EULA、世界或动作范围批准。每个未来提交应是可审阅、可回退的完整变更单元，而不是按单个文件拆分。用户已锁定 Forge 1.20.1 真实客户端控制器与服务端直接权威路径为主路线；服务端驻留身体仅保留历史替代研究。

## 现状、范围与路径约定

当前仓库已从纯蓝图推进到离线契约、策略/认证基础和禁用执行传输切片；`bridge/forge/` 仍没有已启用的 Forge 控制链路，`server/` 仍不是生产编排服务。真实消息限制与双角色心跳证据的范围见[集成实施状态](integration-status.md)，不应被外推为 runtime 或游戏证明。已提交的约束以[产品需求](product-spec.md)、[集成架构](architecture.md)、[接口语义草案](interface-draft.md)、[身体验证](body-validation.md)和[路线图](roadmap.md)为准。

已下载并校验的验证候选清单见[验证资源清单](validation-resource-manifest.md)：Forge `1.20.1-47.4.28` installer/MDK、Minecraft client/server jar、Diet 与 Farmer's Delight。它们不代表兼容、可启动或获准试点；客户端下载/验证记录尚不足以证明完整运行时 libraries/assets 已冻结，配置 hash 仍待生成。C01 的构建依赖下载只验证了最小工程，不等于真实客户端运行时已经构建、启动或通过测试。

Forge 代码根目录 `bridge/forge/`、模组标识 `luosandbox`、包名和 JUnit 已由 C01 固定；实际传输实现、side 目录组织及单/多 JAR 打包仍未决定。AgentLuo 适配器已纳入协调交付范围，但源码仍在其上游仓库以独立原子提交/PR和测试实现；本仓库不复制人格、WorldStage 或 Agent 实现。适配器尚未开始，等待实际接缝确认。

## 共同门槛

- P1 前需冻结候选包、配置和 SHA-256，确定离线登录身份与网络边界，完成隔离世界/区域、备份、人类玩家对照及 P1 runtime 单独批准；若选择源码改动，额外冻结服务端源码基线、补丁、许可证与对应构建/测试步骤
- 离线登录不依赖 Microsoft/Mojang 在线认证，但昵称或派生 UUID 不是可信身份；身体控制激活前仍须独立认证与绑定。不得猜测改名/后端切换后的 UUID 或 playerdata 迁移行为
- 高风险挖掘、放置、战斗、库存和容器变更默认关闭。食物/容器返还仅限经书面授权的隔离身体语义测试，不成为 Agent 的生产能力
- 世界结果不能靠 Git 回退；涉及世界的提交只可回退代码，实际世界须按备份与恢复流程处理

## 主路线与服务端保护顺序

真实客户端是已决定主路线，C07 不等待另一条身体路线的比较。C08 的最小服务端直接权威实现可在 C07 前实施，避免“先允许控制才能验证保护”的循环；实际选用自有伴随模组还是小范围源码改动以复杂度、兼容性证据和可复现性决定，不预设 core fork 技术。任何实际客户端控制前，服务端身份绑定、停止、区域及禁止交互保护必须就绪，缺失时拒绝控制。若主路线不能保持普通玩家食物/Diet、身份绑定、输入清理和恢复不变量，应停止扩展并提交人工决定，而不是自动回退到服务端驻留实体。

## 实现时的测试分层

| 层级 | 可自动执行 | 需要人工/真实游戏 |
| --- | --- | --- |
| 非游戏单元 | 类型、策略、epoch、回执、授权、绑定接口、输入释放和故障状态机 | 无 |
| 构建集成 | 选定 MDK 下的编译、格式、静态检查和不启动游戏的适配测试；若选择源码改动则为固定服务端基线的可复现上游构建/测试 | 依赖与实际 Forge API/源码补丁审阅 |
| 隔离 runtime | 仅保留日志/证据格式校验 | 食物、Diet、容器返还、tick、保存、重启、离线登录 UUID/playerdata、数据包强制与控制丢失 |
| 人类/邀请者 | 测试记录完整性 | 同配置正常玩家基线；2 小时、3–5 人受邀者里程碑，当前未执行 |

连接/heartbeat 失效与模型推理变慢必须分开测试：前者触发停止、保存、移除，后者不得触发断连。重启恢复必须重新认证、观察、对账；每个持久身体身份最多一个活动身体，只有当前 epoch 有效，单个运行时最多一个改世界动作。
